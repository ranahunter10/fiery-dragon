## 2. Volume control, aggregation and dedup

**Kunai.**
- *Map and key.* `FILE_TRACKING` is an LRU of 0x1ffff entries with key `(task_id, i_ino)`, where `task_id = bpf_get_current_pid_tgid()` ([fs.rs:39-90](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-ebpf/src/probes/fs.rs#L39-L90), [utils/bpf.rs:4-6](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-common/src/utils/bpf.rs#L4-L6)) — SRC. The key is per thread, with no device and no generation. Inode collisions across filesystems or PID reuse can suppress a true first read (INF).
- *Re-emit.* The READ and WRITE bits are never cleared; only CLOSE_AFTER_WRITE is, in fput (fs.rs:624-627) — SRC. Nothing deletes entries on exit (SRC, grep). So re-emission happens only after LRU eviction (INF).
- *Throttle.* A throttled event returns *before* its flag is set, so it is retried on the next read. `/etc/` paths bypass the throttle, and `/proc/` reads are silently dropped ([fs.rs:237-255](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-ebpf/src/probes/fs.rs#L237-L255)) — SRC. The throttle map is an `LruPerCpuHashMap<(task, second)>` (fs.rs:92-115) — SRC. That makes the "global" key 0 a per-CPU limit (INF).
- *Counting.* Crossing the limit emits exactly one Task/GlobalThrottleFs error event per window and no count of what was suppressed ([fs.rs:153-173](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-ebpf/src/probes/fs.rs#L153-L173)) — SRC. Defaults: 2048 eps global, 2/3 of that per task ([config.rs:250-251](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai/src/config.rs#L250-L251)) — SRC.
- *Other paths.* WriteClose is deduplicated per (100 ms, task, path) (fs.rs:565-613) — SRC. Socket send is per call, filtered by min length, and sends byte frequencies rather than payload ([send_data.rs:34-110](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-ebpf/src/probes/send_data.rs#L34-L110)) — SRC.

**Tetragon.** `Post rateLimit` hashes (func_id, action, tid | pid | 0, first 40 bytes of up to 5 args) into an LRU `ratelimit_map` sized to 32768 ([ratelimit_maps.h:13-43](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/bpf/process/ratelimit_maps.h#L13-L43), [basic.h:2529-2606](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/bpf/process/types/basic.h#L2529-L2606), consts.go:17) — SRC; documented in [selectors.md:1436-1456](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/docs/content/en/docs/concepts/tracing-policy/selectors.md#L1436-L1456) — DOC. A suppression only sets `*post = false` ([generic_calls.h:1049-1055](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/bpf/process/generic_calls.h#L1049-L1055)), and `POLICY_POST` is counted only on a successful output (:1317-1318) — SRC. I found no suppression counter (INF). Events are clamped to 9000 bytes at the same site — SRC. Cgroup-rate throttling is per CPU and covers only exec/exit ([cgroup-rate.md](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/docs/content/en/docs/concepts/cgroup-rate.md)) — DOC. The userspace export limiter emits an in-band `RateLimitInfo` carrying the dropped count ([ratelimit.go:50-79](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/pkg/ratelimit/ratelimit.go#L50-L79)) — SRC. Aggregation of identical events is OPEN; there is no aggregator package at this HEAD.

**Tracee.** `file_modification_map` (LRU 10240, key `{host_pid, dev, inode}`, [maps.h:368-374](https://github.com/aquasecurity/tracee/blob/2f9dc40c20b17c2ba27f6d92b25e62790bd48a62/pkg/ebpf/c/maps.h#L368-L374), [types.h:657-672](https://github.com/aquasecurity/tracee/blob/2f9dc40c20b17c2ba27f6d92b25e62790bd48a62/pkg/ebpf/c/types.h#L657-L672)) works in three steps. `fd_install` with FMODE_WRITE arms SUBMIT, recording ctime and size. The first `file_update_time`/`file_modified` emits once and sets DONE. `filp_close` emits if ctime or size changed (the btrfs case), then deletes the entry ([tracee.bpf.c:4910-5068](https://github.com/aquasecurity/tracee/blob/2f9dc40c20b17c2ba27f6d92b25e62790bd48a62/pkg/ebpf/c/tracee.bpf.c#L4910-L5068)) — SRC. Plain vfs_read/vfs_write events have no dedup, only scope filters (SRC, tracee.bpf.c:3362-3407).

**Falco.** "Dropping mode" samples rather than dedups: within each second, syscalls after the first `1/sampling_ratio` of it are dropped, subject to per-syscall NEVER/ALWAYS_DROP flags. In-band DROP_E/DROP_X events mark each phase, and the code calls the logic "best effort" because it is not per-CPU ([syscall_exit.bpf.c:63-173](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/driver/modern_bpf/programs/attached/dispatchers/syscall_exit.bpf.c#L125-L173)) — SRC. `drop_failed` returns without a counter ([:244-246](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/driver/modern_bpf/programs/attached/dispatchers/syscall_exit.bpf.c#L244-L246)) — SRC.

**Elastic.** `vfs_write__exit` emits one FILE_MODIFY per successful write unless the pid is "trusted". No dedup or rate limit appears in the BPF code ([Probe.bpf.c:593-646, 770-790](https://github.com/elastic/ebpf/blob/51b6ec73e00b9bb0d8612ae237576b9af410dac6/GPL/Events/File/Probe.bpf.c#L770-L790)) — SRC. Whatever Elastic Defend does downstream is closed source (OPEN).

**Datadog CWS discarders (key design).** A discarder is a kernel-side negative cache: "no loaded rule can match events of type T on this (mount_id, inode)".
- *Creation.* Userspace SECL evaluation decides `IsDiscarder` for the file or up to 3 parents (never `/`) and pushes it over eRPC, skipping re-adds within 2 s ([discarders_linux.go:33-45, 337-397](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/probe/discarders_linux.go#L337-L397), [erpc.h:15-24](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/helpers/erpc.h#L15-L24)) — SRC.
- *Storage.* `inode_discarders` is an LRU of 4096 entries, key `{ino, mount_id, is_leaf}`. The value holds an event mask, per-event expiry, global and mount revisions, and `is_retained`/`expire_at` ([maps.h:92](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/maps.h#L92), [discarders.h:174-234](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/helpers/discarders.h#L174-L234)) — SRC.
- *Check.* The dentry walk checks the leaf and 3 parents. A hit returns DENTRY_DISCARDED, or only flags the event while an activity dump or sampling is active ([dentry_resolver.h:86-99](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/hooks/dentry_resolver.h#L86-L99)) — SRC.
- *Invalidation, three layers.* (1) A global revision, bumped on ruleset change, makes old entries non-discarding ([discarders.h:236-255](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/helpers/discarders.h#L236-L255)). (2) Per-mount revisions (`mount_id % 4096`) are bumped on umount and on directory unlink/rename ([umount.h:74](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/hooks/umount.h#L74), [unlink.h:84-86](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/hooks/unlink.h#L84-L86)). (3) Unlink, rename, link and rmdir mark the inode's entries *retained* for 5 s: they discard nothing and block re-insertion by in-flight userspace events ([discarders.h:257-295](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/helpers/discarders.h#L257-L295)) — SRC. Slot collisions can only over-invalidate (INF).
- *Accounting.* Per-type `discarders_added` and `event_discarded` per-CPU counters ([discarders.h:22-52](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/helpers/discarders.h#L22-L52)) — SRC.

## 3. File identity and path

- Tracee identifies a file by `(dev, inode, ctime)`. Its path walk stops at 20 components and keeps the leaf side ([filesystem.h:229-296](https://github.com/aquasecurity/tracee/blob/2f9dc40c20b17c2ba27f6d92b25e62790bd48a62/pkg/ebpf/c/common/filesystem.h#L229-L296), consts.h:29) — SRC. A long path therefore comes out as a plausible but wrong absolute path with no flag (INF). Disconnected dentries yield `<disconnected>`, and memfds fall back to the dentry name — SRC. Paths are cached in a 5-entry LRU keyed by file_id (filesystem.h:336-355) — SRC.
- Elastic marks a path longer than 100 components with a leading "." ([PathResolver.h:42,121-125](https://github.com/elastic/ebpf/blob/51b6ec73e00b9bb0d8612ae237576b9af410dac6/GPL/Events/PathResolver.h#L121-L125)) — SRC. It reports the inode but not the device in `ebpf_file_info` ([File.h:57-65](https://github.com/elastic/ebpf/blob/51b6ec73e00b9bb0d8612ae237576b9af410dac6/GPL/Events/File/File.h#L57-L65)) — SRC.
- Tetragon sets `UNRESOLVED_PATH_COMPONENTS` when the walk does not finish or the buffer overflows ([bpf_d_path.h:17-30](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/bpf/lib/bpf_d_path.h#L17-L30)) — SRC.
- Kunai stores the path error inside the event ([path/bpf.rs:60-69](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-common/src/path/bpf.rs#L60-L69), [path.rs:30-60](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-common/src/path.rs#L30-L60)) — SRC.
- Datadog caches one `pathnames` entry per dentry, key `{ino, mount_id, path_id}`, using an LRU with **BPF_F_NO_COMMON_LRU** ([maps.h:115](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/maps.h#L115)). `path_id` combines a mount-scoped high id and an inode-hash low id; the low id is bumped on unlink/rename of a file, and on every lookup when nlink > 1 (hardlinks), so cached names cannot be served for a re-linked inode ([filesystem.h:32-75](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/helpers/filesystem.h#L32-L75)) — SRC. It handles overlayfs layers explicitly (`is_overlayfs`, `set_overlayfs_inode`, same file) — SRC. A resolver hit/miss metric exists (`.dentry_resolver.miss`) — SRC.
- Falco takes the path from open arguments plus cwd, in userspace. Open-exit events carry `dev`, `ino` and the overlay layer ([openat.bpf.c:24-66](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/driver/modern_bpf/programs/tail_called/events/syscall_dispatched_events/openat.bpf.c#L24-L66)). Read and write carry only the fd ([event_table.c:98-125](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/driver/event_table.c#L98-L125)) — SRC.
- Pipes and sockets: Kunai and Elastic drop non-regular files ([fs.rs:219](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-ebpf/src/probes/fs.rs#L219), Probe.bpf.c:615-620) — SRC. Pseudo-fs names such as `pipe:[ino]` come from `d_op->d_dname` and are not stored in `d_name`, so a dentry walk yields an empty or bogus name for them (INF).

## 4. Loss accounting

- **Falco** has the most complete scheme. Every drop is counted in both `n_evts` and `n_drops_*`, explicitly so that consumers can compute a ratio ([auxmap_store_params.h:116-124](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/driver/modern_bpf/helpers/store/auxmap_store_params.h#L116-L124)). Buffer drops are split by syscall category ([struct_definitions.h:69-95](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/driver/modern_bpf/shared_definitions/struct_definitions.h#L69-L95)) — SRC. **Relevant to 7.0:** the per-CPU scratch buffer is now a pool claimed by `cmpxchg` on `owner = pid_tgid`. The source comment reads: "a BPF program on a tracepoint is only pinned to its CPU from 7.0 … a preempted filler can also have been migrated". Migration and reentrancy are counted separately (`n_auxmap_migrations`, `n_drops_auxmap_reentrancy[_tail_call]`, `n_drops_auxmap_pool_full`) ([auxmap_store_params.h:62-125, 252-278](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/driver/modern_bpf/helpers/store/auxmap_store_params.h#L252-L278)) — SRC. Falco can alert, log or exit when the drop ratio crosses a threshold, using a token bucket ([falco.yaml:1100-1137](https://github.com/falcosecurity/falco/blob/2be5618cad8beaabc2c1dc02ba5b3a5553ee923f/falco.yaml#L1100-L1137)) — DOC.
- **Tetragon** counts output errors in `sent_failed[msg_op][errno]` ([process.h:603-656](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/bpf/lib/process.h#L603-L656)). Its `tg_errmetrics_map` keys helper errors by (errno, file id, line, helper) ([errmetrics.h:11-27](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/bpf/lib/errmetrics.h#L11-L27)) — SRC.
- **Datadog** keeps a per-event-type `events_stats` count in the kernel plus perf-reader lost counts, tagged by map and event type ([maps.h:181](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/ebpf/c/include/maps.h#L181), [metrics.go:136-145](https://github.com/DataDog/datadog-agent/blob/2215f429e3faefdaf361bca24a31edeb4a8eebda/pkg/security/metrics/metrics.go#L136-L145)) — SRC.
- **Elastic** counts sent/lost per CPU ([Helpers.h:337-349](https://github.com/elastic/ebpf/blob/51b6ec73e00b9bb0d8612ae237576b9af410dac6/GPL/Events/Helpers.h#L337-L349)). A failed per-CPU event-buffer lookup only calls `bpf_printk` (Probe.bpf.c:597-600) — SRC.
- **Kunai** sums perf `Lost` records and logs the top-5 event types by attempted count as "filtering hints" ([main.rs:2789-2830](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai/src/bin/main.rs#L2789-L2830)). The `EVENTS.output` return value is ignored ([perfs.rs:26-40](https://github.com/kunai-project/kunai/blob/4e492b95a0521aae5ab04dd8c98cda0dfdc412d8/kunai-common/src/bpf_events/events/perfs.rs#L26-L40)) — SRC.
- **Tracee** keeps userspace lost counters ([stats.go:100-103](https://github.com/aquasecurity/tracee/blob/2f9dc40c20b17c2ba27f6d92b25e62790bd48a62/pkg/metrics/stats.go#L100-L103)) — SRC.
- **Sysmon** prints a lost-events line and keeps a counter ([sysmonforlinux.c:791-796](https://github.com/microsoft/SysmonForLinux/blob/962934f7e710a8e860ed5020f2068c6eba6aff64/sysmonforlinux.c#L791-L796)) — SRC.
- **Attribution:** no tool attributes drops to a process or file; the finest grain is event type or syscall category (SRC, above). I found no consumer of `recursion_misses` in these trees (OPEN).

## 5. Process/file lifecycle

- Tracee clears per-(pid, file) state at `filp_close`, but deliberately keeps it when ctime and size are unchanged, because a dup'd fd may still write (SRC, comment in §2 range). Its HEAD commit fixes a collision: `fd_arg_path_map` was keyed by timestamp alone, so threads overwrote each other and fd reuse could pick an older path. The key is now (ts, pid_tgid) ([commit 2f9dc40c](https://github.com/aquasecurity/tracee/commit/2f9dc40c20b17c2ba27f6d92b25e62790bd48a62)) — SRC.
- Falco shares the fd table copy-on-write on clone. The source calls ignoring CLONE_FILES and CLOEXEC "an oversimplification" ([parsers.cpp:852-866](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/userspace/libsinsp/parsers.cpp#L852-L866)). A dup2 or a missed close replaces the entry silently. A full 4096-entry table drops new fds without a drop counter at that site ([fdtable.cpp:145-151](https://github.com/falcosecurity/libs/blob/0815626f9fe816aca7fa41cbb776c68770970e16/userspace/libsinsp/fdtable.cpp#L145-L151)) — SRC.
- Tetragon removed FollowFD/UnfollowFD/CopyFD in v1.8: the `fd` type now resolves on its own ([v1.8.0.md:33-35](https://github.com/cilium/tetragon/blob/d86c942441f788cee548b1d849f5e3657bc69d59/contrib/upgrade-notes/v1.8.0.md#L33-L35)) — DOC. The stated reason for the removal is OPEN.
- Kunai never clears state on exit (§2). Fork inheritance does not matter there, because the key is per thread (INF).

## 6. auditd and Sysmon for Linux

- auditctl(8): "The read & write syscalls are omitted from this set since they would overwhelm the logs … the open flags are looked at" instead. `-b` (backlog, default 64) and `-r` (rate) fall back to the failure flag `-f` (silent / printk / panic). `lost` counts records discarded on queue overflow ([auditctl.8](https://manpages.ubuntu.com/manpages/focal/man8/auditctl.8.html)) — DOC. So an auditd "rw" watch records opens with intent, not data flow.
- A full backlog with a long `backlog_wait_time` stalls the processes that generate events ([linux-audit 2020-06](https://listman.redhat.com/archives/linux-audit/2020-June/016639.html)) — BLOG.
- Sysmon for Linux has no read/write events. It infers FileCreate from O_CREAT on a regular file whose atime, mtime and ctime are equal and within 100 ms of the event, and RawAccessRead from opens of block devices ([sysmonFileOpen.c:191-201](https://github.com/microsoft/SysmonForLinux/blob/962934f7e710a8e860ed5020f2068c6eba6aff64/ebpfKern/sysmonFileOpen.c#L191-L201)) — SRC.

## 7. Pitfalls (kernel source and lists)

- **bpf_d_path** is allowed only on security_file_permission, security_inode_getattr, security_file_open, security_path_truncate, vfs_truncate, vfs_fallocate, dentry_open, vfs_getattr, filp_close, plus iterators and sleepable LSM hooks. vfs_read and vfs_write are not on the list ([bpf_trace.c:931-958 @v7.0](https://github.com/torvalds/linux/blob/v7.0/kernel/trace/bpf_trace.c#L931-L958)) — SRC. Calling it on a path reached through a pointer chain was shown to be a use-after-free (2023 report, [LKML](https://lkml.iu.edu/2310.3/05202.html)) — BLOG.
- **fentry/fexit recursion:** `__bpf_prog_enter_recur` skips the program and calls `bpf_prog_inc_misses_counter` when the per-program recursion context is taken ([trampoline.c:1143-1155 @v7.0](https://github.com/torvalds/linux/blob/v7.0/kernel/bpf/trampoline.c#L1143-L1155)) — SRC. Entry and exit misses are independent, so fentry/fexit pairs drift apart ("wildly unreliable" — [lore, Olsa/Starovoitov](https://lore.kernel.org/all/ZBr7Jt9+yr0PHk6K@krava/T/)) — BLOG. The project's E-0089 finding agrees with this.
- **Per-CPU scratch under preemption:** Elastic picks its event buffer by `bpf_get_smp_processor_id()` ([Varlen.h:56-67](https://github.com/elastic/ebpf/blob/51b6ec73e00b9bb0d8612ae237576b9af410dac6/GPL/Events/Varlen.h#L56-L67)) — SRC. On 7.0, where fexit runs with migration disabled but preemptible, two tasks on one CPU could interleave in that buffer (INF). Falco's owner-claimed pool is the counter-design (SRC, §4).
- **LRU is approximate.** Each CPU keeps a local free list (target 4), and eviction batches up to 128 entries ([bpf_lru_list.c:10-14 @v7.0](https://github.com/torvalds/linux/blob/v7.0/kernel/bpf/bpf_lru_list.c#L10-L14), [map_hash.rst:230-244](https://github.com/torvalds/linux/blob/v7.0/Documentation/bpf/map_hash.rst#L230-L244)) — SRC/DOC. One SO user saw 897 entries in a 1024-entry map after 1025 inserts ([SO 75882443](https://stackoverflow.com/questions/75882443)) — BLOG. Updating an *existing* key from a syscall on a full map can evict another entry; a proposed fix was not accepted ([patchew, Jan 2026](https://patchew.org/linux/20260107151456.72539-1-leon.hwang@linux.dev/20260107151456.72539-5-leon.hwang@linux.dev)) — BLOG.
- **Ring buffer vs perf buffer:** the ring buffer orders events across CPUs and fails `reserve` up front, but it has no lost-sample callback, so drops must be counted in BPF ([nakryiko.com](https://nakryiko.com/posts/bpf-ringbuf/)) — BLOG.
- **Faulting string reads:** a `strncpy_from_kernel_nofault` bug on 5.8–6.1 can leak `bpf_prog_active`, after which every kprobe on that CPU is silently skipped ([Tracee filesystem.h:257-272](https://github.com/aquasecurity/tracee/blob/2f9dc40c20b17c2ba27f6d92b25e62790bd48a62/pkg/ebpf/c/common/filesystem.h#L257-L272), [lore](https://lore.kernel.org/bpf/20221110085614.111213-2-albancrequy@linux.microsoft.com)) — SRC/BLOG. It does not affect 7.0 (INF).

## Design lessons for an observe-only capture layer

Everything here is INF: options backed by the evidence above, not decisions.
1. **Key per-(process, file) state on (tgid + start time, dev or mount_id, ino, generation).** Kunai's key has no dev and Tracee's timestamp-only key collided across threads.
2. **Choose "first-per-open" over "first-ever".** Tracee arms at fd_install and clears at filp_close; Kunai clears only by LRU. Only the first gives provenance a defined epoch. Add an exit sweep.
3. **Make every suppression counted and in-band.** Follow Falco (attempted and dropped in both counters, DROP_E/X markers in the WAL), Tetragon's RateLimitInfo and Datadog's event_discarded. Avoid Kunai's single notice per window and Tetragon's uncounted `post=false`.
4. **Discarders are the safe in-kernel dedup**, but only with Datadog's three invalidation layers (global revision, mount revision, inode retention). Without them, rename, unlink or a rule change produces false negatives.
5. **Identity is (mount_id, ino, gen) and the path is metadata.** Resolve the path once, cache it by identity with invalidation, and always flag truncation.
6. **On 7.0, treat per-CPU scratch buffers as shared under preemption.** Claim them by owner as Falco does, or use ringbuf reserve. Export per-program `recursion_misses` as a loss counter.
7. **LRU capacity is not a bound.** Count insert failures and test eviction on the target kernel.
